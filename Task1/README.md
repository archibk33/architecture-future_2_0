## Task1 Архитектура и приоритизация

### Описание задачи
Цель подготовить целевую архитектуру через год и показать поддержку ключевых бизнес сценариев компании. 
Результат должен помочь сократить время подготовки отчетности и обеспечить независимое развитие направлений 
финтех и ИИ с возможностью масштабирования для новых бизнесов.

### Артефакты
1. Диаграмма контейнеров C4 файл containers.puml  
2. Анализ проблемных мест файл problems.md  
3. Приоритизация проблем метод MoSCoW файл prioritization.md

### Описание архитектуры (ключевые решения)
- используем набор коннекторов и легких микросервисов, публикующих события в Kafka. По сути получается не монолитная шина, а свеого рода композиция сервисов и паттернов (cd, outbox).
- Контракты и валидация схема сначала через shema registry (avro schema). Базовая валидация на границе (адаптеры), формальная проверка совместимости при публикации/чтении.
- ФЛК и трансформации быстрые проверки качества/правил и обогащение выполняются в потоковых обработках (flink kafkka). Тяжелые батч преобразования выполняются в ETL оркестрации.
- Процессы оркестрация загрузок и зависимостей в планировщике ETL (airflow). Для длительных бизнес процессов возможно подключение BPMN оркестрации саг при необходимости.
- cырые данные в data lake, агрегаты витрины в облачном вwh. BI и отчетность читают из DWH; события служат источником правды между доменами.
