## Обоснование конфигурации

1. VPC и подсети дают изоляцию и управляемую маршрутизацию. Публичная подсеть используется для доступа из интернета. Приватная подсеть получает доступ наружу через NAT.  
2. Интернет шлюз и маршрут публичной подсети обеспечивают входящий и исходящий трафик для ВМ. NAT и его адрес обеспечивают выход приватной подсети без входящих соединений.  
3. Группа безопасности ограничивает вход на ВМ. SSH только из вашего диапазона. HTTP открыт для простого теста.  
4. ВМ EC2 размещена в публичной подсети. Дополнительный диск EBS хранит данные сервиса. Это разделяет вычисление и хранение.  
5. Объектное хранилище S3 хранит сырые данные. Это удобно для загрузки наборов и для дешевого долговременного хранения.  
6. Все сущности имеют теги. Это упрощает управление ресурсами и учет затрат.  
7. Подход IaC повышает повторяемость. Среды можно воссоздавать одной командой. Изменения проходят через план и легко проверяются.  

## Применение

1. Конфигурация подходит для запуска витрин отчетности и сервисов данных.  
2. Пайплайны могут читать из S3 и писать в хранилище данных в облаке.  
3. Архитектура расширяется новыми подсетями и сервисами без изменения базовой логики.
